## Core UI Rules From This Pass

### 1. The dashboard is the front door, not a wall of modules

- the Home pulse remains primary
- secondary operational surfaces should support the pulse, not compete with it
- dashboard queue surfaces should be compact and drill-in ready

### 2. Summary first, detail on demand

- important summary always stays visible
- deeper operational detail moves behind disclosures, tabs, or drawers
- avoid showing every possible detail at once

### 3. Not every box gets equal weight

- primary command surfaces get the strongest placement
- secondary queues are visually demoted
- informational content should not be the same size as action surfaces

## Hierarchy Rules

### Above the fold

Show first:

- what matters now
- what is at risk
- what needs follow-through
- what the user needs to do next

### Lower on page

Move down or collapse:

- supporting queues
- historical context
- less urgent updates
- secondary reference material

## Card Sizing Rules

### Compact cards

Use for:

- queue previews
- risk items
- follow-through rows
- manager cockpit items

### Standard cards

Use for:

- primary widgets
- key summary modules
- cards that need short explanatory copy plus action

### Avoid

- tall cards with sparse content
- large cards used only to create visual fill
- repeated equal-size cards when only one or two are actually important

## Expansion And Disclosure Rules

### Use tabs when

- the same object has distinct workflow modes
- users should stay in one detail screen but focus on one mode at a time

Examples:

- employee shift detail:
  - execute
  - closeout
  - exceptions

### Use accordions / disclosures when

- content is subordinate to the main workflow
- users benefit from seeing summary first, details second

Examples:

- dashboard queue sections
- updates / notification stacks
- secondary operational modules

### Use drawers when

- the user needs focused drill-in without losing the parent workspace
- the detail is deep enough to deserve temporary focus

### Avoid

- nesting too many disclosure levels
- hiding critical next steps behind multiple clicks

## Dashboard Layout Rules

- Home pulse stays visually dominant
- operational command surfaces should sit in a tighter grid, not a long same-weight stack
- summary metrics should be compact and actionable
- secondary queues should live below the primary dashboard command layer

## Mobile Simplification Rules

- employee-first screens should favor tabs and compact cards over long scrolls
- avoid exposing leadership-density layouts to mobile users by default
- keep primary actions and status readable without opening multiple sections

## Status And Scanability Rules

- surface status, next step, risk, timing, and ownership early
- use short headings
- use explicit wording over vague labels
- use badges and chips to support scanning, not to decorate

## Practical Guardrail

If a visible section does not help the user act, monitor, or decide:

- shrink it
- collapse it
- demote it
- or remove it from the main scan
